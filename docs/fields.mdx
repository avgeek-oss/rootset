Open a table's **Settings → Fields**. The table lists each column's name and type, required setting, default and constraints. Drag the six-dot handle before a name to change its position. Keyboard users can focus the handle, press Enter, select a position with the arrow keys, and press Enter to drop or Escape to cancel. Select **Add field** or **Edit** to open the form.

## Supported types

| Type        | Stored value and browser behaviour                                                                                   |
| ----------- | -------------------------------------------------------------------------------------------------------------------- |
| `text`      | String with an optional maximum character count and allowed values.                                                  |
| `uri`       | Plain string representing a URI. No address-format validation.                                                       |
| `url`       | Plain string representing a URL. No address-format validation.                                                       |
| `image`     | URL stored as a plain string, displayed as a compact image thumbnail. An unavailable image shows a muted image icon. |
| `integer`   | Whole number with optional inclusive minimum and maximum.                                                            |
| `float`     | Number with optional inclusive minimum and maximum.                                                                  |
| `boolean`   | `true` or `false`; displayed in green and orange.                                                                    |
| `date`      | Calendar date such as `2026-10-09`.                                                                                  |
| `time`      | UTC time; the browser edits hours and minutes.                                                                       |
| `date-time` | UTC instant; the browser displays your chosen date/time format.                                                      |
| `json`      | JSON object, array, number, string, boolean or NULL.                                                                 |

Date, time and date-time fields support inclusive minimum and maximum bounds. Date-time bounds use a date picker and default to midnight UTC. URI, URL and image fields have no custom address constraints.

## Required and default values

Optional fields allow `NULL`. Required fields cannot contain `NULL`, but they do not need a constant default. Select **No default** when callers will supply a value, **A literal value** to use a constant when a value is omitted, or **Auto-increment** for an integer generator. There is no separate nullable setting.

Changing an existing column's default or generator only affects new rows. Making a populated field required checks its existing cells; fill any NULL cells explicitly before applying that change. Selecting a default or enabling auto-increment on an existing column does not rewrite its stored values. Adding a new field with a literal default backfills that new column; auto-increment does not backfill existing rows.

Column names use 1–64 letters or underscores. They are the keys used in API row values. Rootset rejects reserved system names.

## Auto-increment integers

For an integer field, select **Default for new rows → Auto-increment**. REST and MCP use the same field definition:

```json
{
  "name": "RECORD_ID",
  "type": "integer",
  "required": true,
  "autoIncrement": true,
  "min": 1
}
```

Omit the property from a new row to generate its value. Supplying an explicit integer preserves it and advances the counter when needed. Supplying NULL preserves NULL for an optional field and fails for a required field. Updates do not regenerate values when the property is absent.

The first generated value is the configured minimum, or 1 when no minimum is set. Enabling generation on a populated column starts above its highest existing integer and preserves every row ID, stored cell value, and row revision. Counters are durable, serialize with table writes, and never move backwards when values are lowered, rows are deleted, or generation is disabled and enabled again. There is no counter-reset operation.

Generated values respect the inclusive maximum and the safe-integer limit of 9,007,199,254,740,991. When no value remains, creation fails with `AUTO_INCREMENT_EXHAUSTED`; the transaction does not publish partial rows. Raising a configured maximum can make more values available. Failed transactions roll back their allocations, and replaying a successful idempotent request returns its original result without allocating again.

Auto-increment cannot be combined with a constant default, including an explicit NULL default. To enable it through `updateField` on a column that already has a default, send `clearDefault: true` beside `field` in the request. The editor does this when switching from a literal default. Schema previews use `clearDefault: true` inside the change's `changes` object. Send `autoIncrement: false` to disable generation; this preserves the counter. Field and schema reads return the flag.

Within each mutation batch, explicit integer values are reserved before any omitted IDs are generated, regardless of row order. Import clients can therefore mix supplied IDs and omitted properties in the same batch. Across separate batches, allocations follow commit order; an explicit ID that conflicts with a previously committed row still fails its unique rule. Declare a [unique rule](/unique-rules) when explicit IDs must also be unique. Auto-increment does not change the built-in Rootset row identifier.

## Allowed values

For a text field, select **Allowed values → Only these choices** in the field editor. Add one or more choices and choose a default when needed. Constrained text cells use a dropdown; optional fields also offer NULL. Enter saves, Tab saves and moves, Escape cancels, and leaving a cell saves through the normal revision checks.

Allowed values are supported only on `text` fields. Supply 1–100 distinct, nonempty strings. Each choice may contain up to 4,096 Unicode characters within the field's character limit; the complete JSON choice list is capped at 65,536 UTF-8 bytes. Choice lists across one table share a 512 KiB budget, leaving space for schema metadata in bounded MCP responses. Matching is exact, including case, spaces and Unicode spelling. Rootset does not trim or rewrite choices. The string `"NULL"` is a value separate from a NULL cell. Duplicate and empty choices are rejected. Optional fields may be NULL; `required: true` prohibits NULL. Any literal default must be an allowed value.

REST/MCP field creation and editing use the same field definition:

```json
{
  "name": "STATUS",
  "type": "text",
  "required": true,
  "default": "active",
  "allowedValues": ["active", "planned", "suspended", "ceased", "unknown"]
}
```

Field and table-schema reads return `allowedValues`. Omit it to preserve a constraint in a patch, or send `allowedValues: null` to remove it from a text field. In the field editor, selecting **Any text** removes the constraint. `[]` is invalid. Converting a text field to another type removes this text-only constraint and still validates the converted values.

Adding or tightening choices checks every existing row before activating the change, including defaults and new-field backfills. A conflict leaves values and schema version unchanged; the error identifies an affected row and field, and the preview lists bounded row conflicts. Removing or renaming an option in use is a constraint change, not a bulk edit. To rename a choice, first allow both names, update the affected cells and default, then remove the old name. Choices, required checks and [unique rules](/unique-rules) apply together on every create, update, batch, paste/import and repair. Changes serialize with writes so waiting writers validate the activated definition.

## Change or remove a field

Editing a field previews the proposed schema change before applying it. Changes validate existing data, and long operations run through the worker. An invalid change fails without silently converting incompatible values. Removing a field also removes its cell history; review any dependent unique rules before removal.
