This is a source and development-evidence review of the 104 named operations. It reviews the core, identity, jobs and installation handlers separately from the contracts implementation. It does not sign off the full implementation, claim 104 successful executions, or replace an immutable release-candidate audit.

The review found a dispatch branch for every operation: 38 identity branches, 39 core/storage branches, 23 jobs branches and four installation branches. The public/internal routes, MCP tools, typed examples, output schemas and generated client share the same catalog. Public OpenAPI describes two raw artifact handoffs; the internal spec also declares the session-only browser download. The 19 protocol, interactive and web transport exceptions are inventoried separately.

The current actual-runtime diagnostic records **37 successful transport operation classes**, alongside **104 tool discoveries and 104 rejected invalid-credential route checks**. These are different measurements. The complete API/OAuth suite's local TAP record reports 340 passes, no failures and no skips in 49.36 seconds. The focused real-runtime artifact-download rerun reports one passing workflow, including both positive and negative MCP binary handoff cases. Neither result is an exhaustive per-operation permission matrix.

## Shared execution and authority

The [HTTP/MCP adapters](../../apps/rootset-api/src/app.ts) authenticate before dispatch, validate strict envelopes, enforce request/response budgets, validate numeric lexemes, supply the surface and request context, and validate the actual response against the catalog schema. Public JSON REST requires API-audience bearer authentication; internal operations require a browser session and same-origin proof for mutations. MCP requires an MCP-resource OAuth actor, forbids cross-origin requests and uses structured typed error results.

[Core authorization](../../packages/core/src/index.ts) refreshes the current actor, resolves table-to-database ancestry, verifies an explicitly supplied parent, checks the selected organisation, scopes, role/resource grants, personal identity and operator requirements, and resolves resource-dependent cases before execution. The [access package](../../packages/access/src/index.ts) supplies the role ceiling and grant intersection. A granted Editor can manage table/schema resources, while membership, team-key, ownership, backup and installation duties retain their respective ceilings. Installation authority is separate from organisation ownership.

Database/table enumeration filters returned metadata to visible targets. Database creation requires organisation-wide manage authority. Retained history on a deleted table/database adds its archive-management gate. `getMutation` resolves the mutation's actual table and reauthorizes `getRow`; its empty initial scope list is not an unrestricted mutation-report grant. `getArtifact` resolves the artifact's original purpose, table/database target, requester or same-user job, and current purpose-specific scopes. Jobs resolve their original operation and target again, including cancellation/retry and worker publication. These dynamic resolvers are part of the authority contract and need explicit negative tests; inspecting the initial scope array alone is insufficient.

Ordinary JSON requests retain the approved 8 MiB budget and a separate ten-second body-read deadline, with `REQUEST_TIMEOUT`/408 declared by the generated schemas. The reviewed browser report passes a 4,200,731-byte batch with 100 committed rows and exact cell readback, prompt declared 9 MiB refusal, and unknown-length chunked overflow refusal through Next. The proxy unit suite also checks unfinished-input cancellation after early rejection and continued SSE output after completed POST input; these focused checks do not measure every result-budget boundary. Raw upload remains 128 MiB. The REST/browser JSON result budget is 8 MiB; the MCP result budget is 1 MiB, including structured-result overhead. Row query pagination defaults to 5,000 for REST and 200 for MCP and accepts 1–25,000 rows, stopping on whole rows at the byte boundary. Query AST/JSON depth, predicate/sort limits, schema versions, optimistic row revisions and signed cursor bindings remain domain checks. Jobs, backups and history-archive metadata lists now accept at most 100 entries, matching their actual service limit.

Core requires an idempotency key for mutations. Row/schema/storage journals and queued admission have their own durable bindings. Key creation/rotation and account-action completion have special one-time-secret replay handling. The new shared control journal binds remaining synchronous identity/jobs/installation mutations to principal, operation, exact business input and an HMAC key digest, committing its receipt with the side effects. The current actual-runtime suite exercises concurrent invitation/action/policy admission, identical replay, changed-input conflict, independent credential outcomes, consumed configuration approval replay and immediate authority loss. This sample establishes concrete replay behavior for those families; it does not replace operation-specific replay and rollback cases for every other branch. Replay must reauthorize the live credential/target before returning a receipt and preserve required domain fields while never redisplaying credentials.
