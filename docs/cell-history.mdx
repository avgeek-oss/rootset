Right-click a cell and select **View cell history**. The modal displays changes in a paginated table, including the previous value, new value and time of change. Dates and times use your display preferences.

Rootset automatically keeps the latest **200 saved changes per cell**. There is no retention policy, archive schedule or history backup setting to configure. A failed edit does not become a saved change.

History exists only while its cell exists. Deleting a row, field, table or database removes the corresponding cell history. Administrators do not retain a separate deleted-data changelog.

## Audit Logs

Open **Operate → Audit Logs** for an organisation-wide chronological table of retained record changes, schema changes, imports, exports, backups and restores.

Filter by **Event**, **Resource**, **Actor** and **When**. Event lists specific actions and outcomes with icons, such as **View export completed**. Search inside the event, actor and resource dropdowns to find an option. Actor groups a person's activity across their sessions; Resource matches the database or table shown in that entry. Actor and resource options come from all permitted retained history, independently of the current page. Dates follow your account preferences. Each page uses the same time cutoff; select the search icon to include newer events. A record link opens its full-record drawer. Request links open the corresponding import, export, backup attempts or restore attempts page. Deleted resources keep their schema and request metadata but have no live link. Tables in maintenance show their status without a live link.

Select **Details** at the end of an entry to open its context as read-only JSON. Field reorders show the saved names in their previous and new order. Other entries show brief context such as changed attributes, affected fields and record counts, request options, or backup settings. Details load on demand. Older rule and relation events that did not retain this context say so; later changes do not reconstruct missing history.

Audit logs follow current permissions. Record changes require row and history read access. Background requests follow the same purpose and ownership checks as their request pages; administrators can inspect all requests they are authorised to read. Backup and restore events are available only to administrators with the required backup access. Personal saved views and raw cell values, job payloads, provider errors and credentials do not appear in audit log search.

Record activity is a summary of retained cell history, grouped by mutation. It follows the same 200-change limit and deletion behaviour described above; it is not a permanent record-deletion log. Imports appear as validation and import requests rather than one event per imported record. Event names include the outcome, such as **View export requested**, **View export completed** or **View export failed**, and can be searched by their full name. Job requests and terminal outcomes are retained separately, so a failed attempt remains visible after a retry. Successful schema changes and restores use their committed resource history to avoid duplicate completion events. Restored record and schema history keeps its original timestamps; operational job queues and their activity are not restored from the package.
