Use an API key to connect a script or application to Rootset's REST API. Create a personal key for your own tools, or a workspace key for shared automation.

## Create a personal API key

1. Open **Account Settings → API Keys** and select **Create API key**.
2. Give the key a name, such as **Catalog reader**, then choose its permissions and expiry.
3. Select **Create key** and copy the secret. Rootset shows the full key only once.

A personal key follows your current team role and workspace membership. **Read-only** can view data, **Edit** can also create, update and delete records, and **Administrative** can manage databases, tables, fields and team settings. Only the permissions available to your role appear in the form.

## Create a workspace API key

Only team admins who can access a workspace can create keys for its shared scripts and services.

1. Open **Settings → Workspace Settings → API Keys** and select **Create API key**.
2. Name the service that will use it, then choose its permissions and expiry.
3. Select **Create key** and save the secret in the service's secret store.

Workspace keys belong to one workspace and cannot access another. Administrators can create, rotate and revoke them from the same page.

Existing team API keys are revoked by the workspace upgrade. Create replacement workspace keys and update your scripts.

## Make your first request

Set your installation's public API URL and enter the key when prompted:

```bash
export ROOTSET_API_ORIGIN="https://rootset-api.example.com"
read -rs ROOTSET_API_KEY
export ROOTSET_API_KEY

curl --fail-with-body "$ROOTSET_API_ORIGIN/v1/me" \
  --header "Authorization: Bearer $ROOTSET_API_KEY"
```

This read-only request returns your organisation context and capabilities. Call [list workspaces](/api-reference/listWorkspaces) to discover your accessible workspace IDs. Pass an explicit `workspaceId`, including for Default, when calling workspace-scoped endpoints, such as [listing databases](/api-reference/listDatabases). The URL and key are client settings; use the API address rather than the web application's address.

Send the same `Authorization` header with other requests in the [API reference](/api-reference/request-conventions). A `401` response means authentication failed; a `403` response means the credential does not have access to that operation. Expired or revoked keys stop working.

Use [MCP connections](/mcp-connections) to connect an AI assistant through browser sign-in instead of an API key.
