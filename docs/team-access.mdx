Rootset serves one team per installation. Admins manage its people in **Team Settings → Members**. Invite a person by email and choose their role; SMTP delivers the invitation.

| Role   | Permissions                                                                                                                                       |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Viewer | Read tables and cell history, filter data, and request exports.                                                                                   |
| Member | Viewer access plus create/edit databases, tables and fields, manage unique rules, and create/edit/delete rows. Cannot delete databases or tables. |
| Admin  | Member access plus delete databases/tables, manage people and workspace API keys, and administer the installation.                                |

A person's current role applies to their browser session, personal API keys and OAuth connections. API permissions cannot elevate a person beyond their role. Roles apply in every workspace a person belongs to; [workspace](/workspaces) membership limits which databases they can access. Workspace API keys belong to the workspace and are managed by Admins; they do not depend on the creator remaining a member.

Database deletion in the browser asks an Admin to confirm their identity with a password or passkey. Other authorised operations execute directly; there is no approval-ticket workflow.
