## Access and behavior

Requires a current workspace role of **Member** or higher. The connection needs `schema:manage` scope.

- This tool changes data or starts work. Confirm the target and input before calling it.
- Keep the same `idempotencyKey` when retrying an unchanged request; use a new key for different input.
- Read the current table schema before supplying `expectedSchemaVersion`.
- A returned job is pending work. Use [rootset_get_job](/mcp-reference/rootset_get_job) to check its final result.

## Arguments

| Argument                          | Required | Type            | Details                                                            |
| --------------------------------- | -------- | --------------- | ------------------------------------------------------------------ |
| `orgId`                           | Yes      | string          | Workspace ID returned by rootset_get_context.                      |
| `databaseId`                      | Yes      | string          | ID of the database to work with.                                   |
| `tableId`                         | Yes      | string          | ID of the table to work with.                                      |
| `expectedSchemaVersion`           | Yes      | integer         | Current version returned by the table schema.                      |
| `fieldIds`                        | Yes      | array of string | All field IDs in the desired presentation order.                   |
| `referencedTableId`               | Yes      | string          | —                                                                  |
| `referencedRuleId`                | Yes      | string          | —                                                                  |
| `expectedReferencedSchemaVersion` | Yes      | integer         | —                                                                  |
| `idempotencyKey`                  | Yes      | string          | Stable caller-provided key across retries of this exact operation. |
