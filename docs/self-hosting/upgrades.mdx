Choose a published version from [GitHub Releases](https://github.com/avgeek-oss/rootset/releases). Read its release notes for configuration changes, then take a [recoverable backup](/self-hosting/backup).

Use the same release version for the API, worker and UI. Keep the PostgreSQL data, object storage, application secret and encryption keys.

## Docker Compose

Download the new release's Compose file as described in [Docker Compose installation](/self-hosting/installation/docker-compose). Preserve your existing `.env` and review any new configuration settings.

```bash
docker compose pull
docker compose stop api worker web
docker compose run --rm migrate
docker compose up -d --wait
docker compose ps
curl --fail http://localhost:4310/health/ready
```

Include `--profile local-db` when using bundled PostgreSQL. Keep the Compose project name and named volumes. Do not use `docker compose down --volumes` during an upgrade.

## Towbar

Update the API, worker and UI image references in your deployment repository to the chosen version, then sync it in Towbar. Stop the existing API and worker before starting the upgrade.

Deploy the worker first so its migration hook completes and its heartbeat becomes available. Deploy the API next, wait for readiness, and then deploy the UI. Keep the datastore and persistent volumes in place.

## After upgrading

Verify sign-in, open a table, and confirm that an export completes and downloads. If migrations or readiness checks fail, inspect the first error before continuing.

Database migrations run through the normal migration command. Unknown or modified migration histories stop the upgrade without resetting the installation; do not edit stored checksums to force it through.

An image rollback does not undo database changes. To recover an earlier schema, restore the matching installation backup and configuration.
