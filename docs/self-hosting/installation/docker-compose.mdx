Install Rootset with Docker Compose. The steps below include PostgreSQL, so you do not need to set up a separate database.

## Before you start

You need Docker Engine with Compose 2.23.1 or later, a private S3-compatible bucket, SMTP for account emails, and two HTTPS domains: one for Rootset and one for its API. A reverse proxy routes those domains to the containers.

The supplied memory caps total 8 GiB, including bundled PostgreSQL. Leave additional memory for the host.

## 1. Download the installation files

Create a directory and download both files from the latest [GitHub release](https://github.com/avgeek-oss/rootset/releases):

```bash
mkdir rootset
cd rootset
curl --fail --location https://github.com/avgeek-oss/rootset/releases/latest/download/compose.images.yaml -o compose.yaml
curl --fail --location https://github.com/avgeek-oss/rootset/releases/latest/download/rootset.env.example -o .env
chmod 600 .env
```

For a specific version, download both files from that release instead. The Compose file pins all application images to the same release. Published images support Linux AMD64 and ARM64.

## 2. Set your domains and secrets

Open `.env` and replace these values:

| Setting                  | What to enter                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `ROOTSET_WEB_URL`        | Your Rootset URL, such as `https://rootset.example.com`.                                                            |
| `ROOTSET_API_URL`        | Your API URL, such as `https://rootset-api.example.com`.                                                            |
| `ROOTSET_SECRET`         | A generated application secret. You also use it to claim the installation.                                          |
| `ROOTSET_ENCRYPTION_KEY` | A different generated encryption key.                                                                               |
| `POSTGRES_PASSWORD`      | A third generated value for the bundled database password. Uncomment this setting.                                  |
| `ROOTSET_DATABASE_URL`   | `postgres://rootset:your-generated-password@postgres:5432/rootset`, using the same password as `POSTGRES_PASSWORD`. |

Run this command three times to generate a separate value for each secret:

```bash
openssl rand -hex 32
```

Also configure the required storage and email services:

| Setting                 | What to enter                                    |
| ----------------------- | ------------------------------------------------ |
| `ROOTSET_S3_ENDPOINT`   | Your S3-compatible endpoint URL.                 |
| `ROOTSET_S3_BUCKET`     | An existing private bucket for export artifacts. |
| `ROOTSET_S3_ACCESS_KEY` | The bucket's access key.                         |
| `ROOTSET_S3_SECRET_KEY` | The matching secret key.                         |
| `ROOTSET_SMTP_HOST`     | Your SMTP server hostname.                       |
| `ROOTSET_EMAIL_FROM`    | Your sender address.                             |

Set the SMTP port, TLS mode and credentials to match your provider. See [Configuration](/self-hosting/configuration) for these settings and the S3 region.

Keep `.env` private. Retain the same application secret and encryption key across restarts, upgrades and restores.

## 3. Start Rootset

```bash
docker compose --profile local-db up -d --pull always --wait
```

This starts PostgreSQL, the API, worker and UI. The bundled database creates an ordinary `rootset` owner, and migrations run before the API and worker start. PostgreSQL data persists in the `postgres-data` Docker volume. Keep the worker running for background jobs.

## 4. Route your domains

Configure your reverse proxy on the Docker host:

| Public domain                 | Forward to              |
| ----------------------------- | ----------------------- |
| Your `ROOTSET_WEB_URL` domain | `http://127.0.0.1:4300` |
| Your `ROOTSET_API_URL` domain | `http://127.0.0.1:4310` |

Enable HTTPS for both domains. The worker and database stay private. If your proxy runs in a container, connect it to the Compose network instead of using the host's loopback addresses. See [Security](/self-hosting/security).

## 5. Create your workspace

Open your Rootset URL, enter the configured `ROOTSET_SECRET` and create the first administrator. This account is verified automatically. Choose **Create database** to start adding tables and records.

Check readiness on the Docker host:

```bash
docker compose --profile local-db ps
curl --fail http://localhost:4310/health/ready
curl --fail http://localhost:4300/
```

If startup fails, check [Troubleshooting](/self-hosting/troubleshooting). Follow [Upgrades](/self-hosting/upgrades) when updating an existing installation.

## Use an existing database

Use PostgreSQL 18 and set `ROOTSET_DATABASE_URL` in `.env` to a connection URI reachable from the containers. Use an ordinary database owner that can create schemas and the `pgcrypto` extension, without superuser or `BYPASSRLS` privileges. `localhost` inside a container refers to that container, not the Docker host.

Start without the bundled database profile:

```bash
docker compose up -d --pull always --wait
```

`POSTGRES_PASSWORD` is not needed for this option. Continue with domain routing and workspace setup above.
