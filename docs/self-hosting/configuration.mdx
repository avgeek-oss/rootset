Configure the API and worker with the same database, application secrets, public URLs, S3 source and SMTP settings. With Docker Compose, put them in your private `.env` file. With Towbar, use runtime secrets.

## Database and public URLs

Use an ordinary PostgreSQL database owner with permission to create schemas and the `pgcrypto` extension. The API, worker and migrations use this connection.

```dotenv
ROOTSET_DATABASE_URL=postgres://rootset:your-password@postgres:5432/rootset
ROOTSET_WEB_URL=https://rootset.example.com
ROOTSET_API_URL=https://rootset-api.example.com
```

The UI connects directly to the API. Compose supplies `ROOTSET_PUBLIC_API_ORIGIN` to the UI from `ROOTSET_API_URL`. For other deployments, set that UI variable to the same public API URL.

## Application secrets

Generate each value separately with `openssl rand -hex 32`. Keep the same values across restarts and upgrades, and store a recoverable copy outside Rootset.

```dotenv
ROOTSET_SECRET=replace-with-a-generated-secret
ROOTSET_ENCRYPTION_KEY=replace-with-a-separate-64-character-hex-key
```

The application secret is also used to claim the first administrator account. The encryption key protects private artifacts; replacing it does not unlock existing artifacts.

## S3 source

Create a private S3-compatible bucket for export artifacts. Give the API and worker credentials scoped to that bucket.

```dotenv
ROOTSET_S3_ENDPOINT=https://s3.example.com
ROOTSET_S3_REGION=us-east-1
ROOTSET_S3_BUCKET=rootset-artifacts
ROOTSET_S3_ACCESS_KEY=your-access-key
ROOTSET_S3_SECRET_KEY=your-secret-key
```

Use the endpoint and region supplied by your storage provider. Downloads are authenticated through Rootset; the bucket does not need public access.

## SMTP

Rootset uses SMTP for invitations, email verification and account recovery. Use a sender your email provider has verified, and match its port and TLS settings.

```dotenv
ROOTSET_SMTP_HOST=smtp.example.com
ROOTSET_SMTP_PORT=587
ROOTSET_SMTP_SECURE=false
ROOTSET_SMTP_USER=your-smtp-user
ROOTSET_SMTP_PASSWORD=your-smtp-password
ROOTSET_EMAIL_FROM=Rootset <rootset@example.com>
```

This example uses STARTTLS on port 587. For implicit TLS, providers commonly use port 465 with `ROOTSET_SMTP_SECURE=true`. Omit the user and password only if your SMTP service does not require authentication.

## Database backup source

To enable [database backups](/backups), add these settings to the **worker only**. Backup storage is separate from the S3 source used for export artifacts.

```dotenv
ROOTSET_BACKUP_S3_ENDPOINT=https://backups.example.com
ROOTSET_BACKUP_S3_REGION=us-east-1
ROOTSET_BACKUP_S3_ACCESS_KEY=your-backup-access-key
ROOTSET_BACKUP_S3_SECRET_KEY=your-backup-secret-key
ROOTSET_BACKUP_ENCRYPTION_KEY=replace-with-a-separate-64-character-hex-key
```

Generate the backup key separately with `openssl rand -hex 32` and keep it outside Rootset. Existing backups require the key that encrypted them. All backup-enabled workers must use the same storage settings and key.

Create the destination bucket before saving a schedule. Credentials need read/write access, multipart upload and abort permissions, and permission to delete destination-test probes. Configured backup retention also needs permission to delete saved backup objects.

<Accordion title="Additional backup settings">

| Variable                             | Default                  | Purpose                                                                |
| ------------------------------------ | ------------------------ | ---------------------------------------------------------------------- |
| `ROOTSET_BACKUP_S3_FORCE_PATH_STYLE` | `true`                   | Set to `false` if your provider requires virtual-host addressing.      |
| `ROOTSET_BACKUP_TEMP_DIR`            | Artifact spool directory | Private writable disk space for preparing a complete encrypted backup. |
| `ROOTSET_BACKUP_MAX_BYTES`           | 32 GiB                   | Compressed encrypted package limit; at most 63 GiB.                    |

Keep space for a complete backup plus the one-GiB reserve. Compose uses the worker's disk-backed artifact spool.

</Accordion>

## Docker Compose settings

The downloaded Compose file selects the release version. No version environment variable is needed.

| Variable                  | Default                  | Purpose                                                     |
| ------------------------- | ------------------------ | ----------------------------------------------------------- |
| `ROOTSET_COMPOSE_PROJECT` | `rootset`                | Keep this stable to reuse the installation's named volumes. |
| `ROOTSET_API_BIND`        | `127.0.0.1`              | API bind address.                                           |
| `ROOTSET_WEB_BIND`        | `127.0.0.1`              | UI bind address.                                            |
| `ROOTSET_API_PORT`        | `4310`                   | API port.                                                   |
| `ROOTSET_WEB_PORT`        | `4300`                   | UI port.                                                    |
| `POSTGRES_PASSWORD`       | Required with `local-db` | Password used for the bundled PostgreSQL database.          |

Keep environment files outside Git. Rootset stores data in UTC; people choose their own display timezone and date format in Preferences.
