Open a table's **Export Requests** page and select **Create export request**. Choose **CSV** or **JSONL**, then select **Start export**.

Each request exports a complete snapshot of the table: every row and every field. You do not select individual fields, and spreadsheet filters do not limit the export. The worker prepares the artifact; the requests table shows progress and the download action when ready. Viewers can request exports of data they can read.

## Export a database

Open a database and choose **Data → Export Requests**, then **Create export request**. Choose CSV or JSONL for the table data and start the export. The worker prepares one ZIP containing every active table, including empty tables, from the same consistent database snapshot.

The ZIP contains `database.json`, a versioned `manifest.json`, a short `README.txt`, and a folder for each table under `tables/<table-id>/`. Each folder includes `schema.json` and `data.csv` or `data.jsonl`. Schema files include table details, ordered field definitions, active unique rules and foreign keys. The manifest maps table IDs to names and records schema versions, actual row counts, snapshot time and file checksums. Internal physical database identifiers are excluded.

The requests table shows table and row counts when complete. Downloads use the existing expiring artifact flow and require current database, row and schema read access. Cancellation, retries and job visibility follow the same ownership rules as table exports. Record writes continue during extraction; schema changes and deletion coordinate with the snapshot lock. Tables undergoing maintenance must finish before an export can begin.

Database exports use the normal export storage configured for the worker; backup storage configuration is not required. They include schema and record values, excluding accounts, credentials, comments and retained history. They do not configure backup schedules or provide a restore/import operation.

## Data formats

| Format | Use it for                                               |
| ------ | -------------------------------------------------------- |
| CSV    | Spreadsheet tools and tabular processing.                |
| JSONL  | One JSON object per line for scripts and data pipelines. |

Downloads require current access to the source table and use expiring artifact access. Keep the exported file if you need it later. CSV and JSONL serialize values according to their format; the UI's `NULL` label is not a replacement for JSON's native `null`.

Exports are data downloads, not an in-app backup or restore mechanism. Rootset does not import these files through the UI.
