Double-click a cell to edit it in place. Press Enter to commit or Escape to cancel. Editors follow the field type: numbers, booleans, calendar/time controls, text and JSON. URL and image cells edit the underlying string.

The selected cell uses the green theme highlight. If a value is invalid or saving fails, Rootset shows a toast and returns the cell to its previous saved value. There is no persistent inline error message.

## NULL values

Right-click an optional cell and select **Set to NULL**. `NULL` is distinct from an empty string, zero, `false` or the string `"NULL"`. Required fields cannot be set to NULL.

## Undo

Press **Cmd+Z** on macOS or **Ctrl+Z** on Windows/Linux to revert saved cell edits one at a time in the current table session. Rootset confirms an undo with a toast. While an editor is active, the shortcut follows the editor's normal text undo. There is no redo. Undo does not restore deleted rows or resources.

## Delete a row

Right-click the row-number cell or a data cell and select **Delete row**. Rootset highlights the affected row in red while the confirmation dialog is open. Deleting removes the row, its cell history and comments, and cannot be undone.

## Discuss a row

Select the speech bubble beside the row number to open its comments. The number shows how many comments the row has. Keyboard users can navigate to that column and press Enter or Space. On a phone, tap the same control to open the discussion.

Viewers can read discussions. Members and administrators can add plain-text comments of up to 4,096 characters. Press **Cmd+Enter** on macOS or **Ctrl+Enter** elsewhere to post. Authors with write access can permanently delete their own comments; administrators can delete any comment they can access. Comments cannot be edited. Deletion does not leave a placeholder body.

Comments preserve the author's name at posting time, even if the account is later deleted. Personal API keys and MCP connections use the authenticated person's name; team keys use the key name. Names cannot be supplied by clients.

The Comments column is a system control. It cannot be renamed, moved into the field schema, assigned a type, edited as cell data or exported as an ordinary field. Posting or deleting a comment does not change the row revision or table schema version.

REST and MCP expose `listRowComments`, `createRowComment`, `deleteRowComment` and `countRowComments`. Counts accept at most 200 row IDs per request and omit missing rows. Discussion pages contain at most 50 comments in chronological order and use opaque cursors. Create/delete requests require an idempotency key; retry an unchanged request with the same key. During the standard receipt lifetime, retrying a deleted comment's creation returns its original ID without recreating it. Receipts contain IDs and status, not comment bodies.

## Loading more rows

Rootset renders the visible rows and requests bounded windows as you scroll. It does not load every record into the browser at once. The row number is a position in the current view; the API row ID is the stable identifier. Filtering changes the view without modifying the records.
