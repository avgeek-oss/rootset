Select **Add record** to create a record in a drawer. Required fields, choices, defaults, automatic IDs and NULL values use the table’s schema. Select a row and choose **Open record** from the table actions menu to edit every field, including fields hidden in the spreadsheet. Save with **Cmd+Enter** on macOS or **Ctrl+Enter** elsewhere. Failed validation keeps the draft and focuses the affected field. Unsaved changes require confirmation before closing; concurrent updates require reloading the saved record before retrying.

Use [Import Requests](/import-requests) to append records from CSV or JSONL. Select record checkboxes for [bulk field updates, duplication and deletion](/bulk-rows).

Double-click a cell to edit it in place. Press Enter to commit or Escape to cancel. Editors follow the field type: numbers, booleans, calendar/time controls, text and JSON. URL and image cells edit the underlying string.

JSON fields use a code editor with syntax highlighting, line numbers and automatic indentation in the record drawer and spreadsheet. Enter adds a line; **Cmd+Enter** or **Ctrl+Enter** saves. The inline editor also provides **Format**, **Save** and **Cancel**. JSON validation and NULL handling follow the same field rules as other record updates.

The selected cell uses the green theme highlight. If a value is invalid or saving fails, Rootset shows a toast and returns the cell to its previous saved value. There is no persistent inline error message.

## NULL values

Right-click an optional cell and select **Set to NULL**. `NULL` is distinct from an empty string, zero, `false` or the string `"NULL"`. Required fields cannot be set to NULL.

## Generate integer IDs on creation

An integer field can use [auto-increment](/fields#auto-increment-integers). When creating rows through the API, MCP, or a batch/import client, omit that property to generate its value on the server. Explicit IDs remain unchanged and advance the counter. A supplied NULL is an explicit cell value, so it does not request generation. Editing an existing row never regenerates an omitted ID.

## Undo

Press **Cmd+Z** on macOS or **Ctrl+Z** on Windows/Linux to revert saved cell edits one at a time in the current table session. Rootset confirms an undo with a toast. While an editor is active, the shortcut follows the editor's normal text undo. There is no redo. Undo does not restore deleted rows or resources.

## Delete a row

Right-click the row-number cell or a data cell and select **Delete row**. Rootset highlights the affected row in red while the confirmation dialog is open. Deleting removes the row, its cell history and comments, and cannot be undone.

## Discuss a row

Select the speech bubble in the first column, beside the row number, to open its comments. A filled bubble in the theme color marks rows with comments; an empty discussion has a muted outline. Keyboard users can navigate to the first column and press Enter or Space. On a phone, tap the same control.

Comments open in a panel that slides in from the right and fills the screen on a phone. The comment list scrolls independently, with the heading at the top and the comment composer at the bottom.

Viewers can read discussions. Members and administrators can add plain-text comments of up to 4,096 characters. Press **Cmd+Enter** on macOS or **Ctrl+Enter** elsewhere to post. Authors with write access can delete their own comments; administrators can delete any comment they can access. Deletion permanently clears the content and records the deletion time, while retaining the author and original timestamp. The panel shows _comment deleted_ in muted text. Comments cannot be edited, and deleted entries cannot be restored or removed from the discussion through comment operations.

Comments preserve the author's name at posting time, even if the account is later deleted. Personal API keys and MCP connections use the authenticated person's name; team keys use the key name. Names cannot be supplied by clients.

The comment icon is a system control in the row-number column. It cannot be renamed, moved into the field schema, assigned a type, edited as cell data or exported as an ordinary field. Posting or deleting a comment does not change the row revision or table schema version.

Row reads and paginated row responses include `hasComments` as system metadata alongside `values`. The spreadsheet uses this flag for its comment indicator and fetches comment contents only when a discussion is opened. Browsing and scrolling do not send comment-count requests. Deleted entries remain part of the discussion, so the icon stays filled even when every comment's content has been deleted.

REST and MCP expose `listRowComments`, `createRowComment`, `deleteRowComment` and `countRowComments`. Explicit count requests remain available for callers that need exact totals; they include deleted entries, accept at most 200 row IDs and omit missing rows. Discussion pages contain at most 50 entries in chronological order and use opaque cursors. Each entry has a nullable `deletedAt`: active comments return `null`, and deleted comments return an ISO timestamp with an empty `body` and `canDelete: false`. Create/delete requests require an idempotency key; retry an unchanged request with the same key. During the standard receipt lifetime, retrying a deleted comment's creation returns its original ID without recreating its content. Receipts contain IDs and status, not comment bodies.

## Loading more rows

Rootset renders the visible rows and requests bounded windows as you scroll. It does not load every record into the browser at once. The row number is a position in the current view; the API row ID is the stable identifier. Filtering changes the view without modifying the records.

The **Rows** sidebar item shows the table's total row count. With filters applied, the `#` heading also shows the matching count in parentheses. A `~` prefix marks an estimate, such as `# (~1,244)`; it disappears when the loaded results establish an exact count. No matches shows `# (0)`.
