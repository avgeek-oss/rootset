# Rootset contracts

This package defines the shared limits, field and row values, typed query language, domain operations, transport schemas, and generated descriptions. Browser editors, storage, REST and MCP use these definitions.

`FieldDefinitionSchema` validates complete field definitions. A field has one `name` for its UI label and row API property, matching `/^[A-Za-z_]+$/` with a maximum of 64 characters. Stable field IDs remain unchanged on rename. `assertFieldNames` rejects reserved names and case-insensitive collisions. `FieldInputSchema` validates new field definitions without a server-generated ID. `validateCell` applies a field's type, nullability and bounds; it emits canonical UTC temporal values. `validateValues` resolves property names or stable field IDs, applies creation defaults, rejects unknown/system writes, and preserves omitted patches. `assertRowBytes` measures the complete user values under stable field IDs, including nulls, against the 65,536-byte limit.

`canonicalJson` validates finite JSON-compatible values and delegates deterministic serialization to `json-canonicalize`. Finite float cells can exceed the safe-integer range. JSON cells use `canonicalValue`, which also rejects unsafe integral numbers. `parseStrictJson` detects duplicate keys, unsafe integral lexemes, invalid Unicode and excess depth before ordinary parsing can discard them. Transport adapters can permit finite floats with `safeIntegers: false`, then apply the table-specific integer/JSON validation. `decodeJsonBytes` rejects malformed UTF-8. Decode limits account for request-envelope nesting; each JSON cell independently has a 32-level limit.

`validateQuery` validates field references and supported type/operator pairs. Its iterative preflight rejects excessive depth before recursive schema traversal. Filter values use type validation without applying populated-cell min/max bounds. Queries remain parameterized and free of raw SQL; storage owns compilation, signed cursors and timeout enforcement.

Transport decoding can collect `NumberLexeme` entries through `onNumber`. `assertSchemaNumberLexemes` validates integer envelope properties, `assertValueLexemes` checks row cells, and `assertFieldDefinitionLexemes` checks defaults and bounds. `assertQueryLexemes` applies the same source-number rules to scalar, list and structured JSON predicates. This keeps a fractional input that rounds to an integer from being accepted as an integer field value or filter.

The operation catalog contains the supported business, personal security and installation tasks for one organisation. Roles are admin, editor and viewer. Admins manage the installation, members and schema; editors write rows and import; viewers read and export. Every role can manage its own profile, security and personal API keys. Personal keys inherit the current user role and have no selected scopes or resource targets. OAuth consent selects operation scopes under the current role ceiling. Organisation lifecycle, resource grants, organisation audit, account deletion and team keys are absent from every generated surface. Each operation declares REST routing, its MCP tool, input/output schemas, scopes, role requirements, idempotency, step-up and job behavior. Read-only classification is explicit for POST queries and previews. A transport adapter cannot replace domain permission checks.

`getSchemaOperation` accepts a journal ID or the originating schema job ID. `SchemaOperationReportSchema` preserves the journal's raw kind and recovery state alongside a canonical phase, typed business request, public table/field snapshot, optional reconstructed field change, and safe verification metadata. Physical identifiers, DDL, execution context, credential data and idempotency hashes stay internal. Schema job results can expose `schemaOperationId`; the core verifies the requested table before mapping a journal or job alias. An older journal without a field target ID cannot reconstruct that change unless its bound job request supplies the missing argument.

Run `pnpm contracts:generate` from the repository root to refresh `generated/`. It produces public/internal OpenAPI 3.1.2 documents, MCP schemas, an operation coverage inventory, a typed client, and a deterministic digest manifest. `pnpm contracts:generate --check` detects drift. MCP output schemas include success and typed error alternatives so compatible clients can validate structured errors.

`pnpm --filter @rootset/contracts test` checks boundaries, malformed values, the operation inventory, generated references/examples, the client with the real TypeScript compiler, and adapter execution. These tests establish shared-contract behavior; PostgreSQL, browser, OAuth and full-scale evidence remain separate verification requirements.
