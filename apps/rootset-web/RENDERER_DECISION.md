# Spreadsheet renderer

Rootset uses React Data Grid 7.0.0-beta.61 with its published stylesheet. This version supports the React 19 stack used by Next.js and HeroUI. The library owns row and column virtualization, resizing, frozen columns, roving focus and keyboard navigation. Rootset sets the supported `rowHeight` prop to 32 px for a compact table, persists column widths and freezes the row-number column. Date and date-time columns have wider defaults to keep the complete inline input visible. Field order comes from the table schema.

Grid appearance uses the library defaults. Integration CSS sizes the grid to its pane, chooses the light or dark scheme, highlights selected ranges with the library's own color variable, and allows inline validation feedback to extend below an editing cell. Column headers use medium weight. It does not replace grid borders, spacing, selected-cell outlines or resize handles.

The API supplies bounded 200-row windows. First, middle, last and explicit row-position navigation use server query sessions and anchors; the browser never creates a spacer for millions of rows. React Data Grid virtualizes each loaded window. The row-number column and live announcement report logical positions; the grid's ARIA indices describe its loaded window. A cache retains at most five windows within a 32 MiB encoded-value budget and clears when schema, authority or query identity changes. TanStack Query stores table and schema metadata separately.

Single click selects; double-click, Enter, F2 or typing opens a typed inline editor. Column-name tooltips expose the field type on hover and focus. Right-clicking a cell opens null, history and deletion actions; the # header opens Go to row. Floating Filter and Add row icon buttons sit at the bottom right so the table occupies the former title-toolbar space. Add row opens one responsive form with all typed fields. Rootset provides these editors and server mutation handling, while the library handles the grid layout and navigation. Drafts stay local until a mutation returns a committed revision. Validation and server failures retain them; version conflicts require explicit review before retry. Leaving an unsaved editor discards its local draft without a confirmation; pending saves remain protected.

Shift selection and lossless TSV copy remain application behavior. Paste previews use the shared atomic mutation schema. Pastes beyond the loaded window or atomic limit open the import workflow and are not reported as committed.

Current verification uses `src/components/cells/CellEditor.browser.spec.ts` against a real local API, worker and PostgreSQL fixture. It covers all eight editors, strict validation, uniqueness and version conflicts, locked pending saves, keyboard focus, time-zone conversion, null semantics, compact rows, context menus and the add-row form. Unit tests cover cache eviction and byte bounds, clipboard parsing, validation and time-zone conversion. Local browser evidence is distinct from full-scale performance and native accessibility acceptance.

Older reports and standalone scripts under `tests/` describe the former custom DOM renderer, earlier authentication/navigation and prelaunch fixtures. Their recorded timings and accessibility results are historical; they do not establish acceptance of React Data Grid. Full-scale browser and native-assistive-technology sign-off remains pending.

Account settings use the published Avgeek design-system patterns. Browser requests go directly to the configured public API origin; the Next service serves the UI shell independently. Credentials and disposable local fixture data are never committed to browser evidence.
